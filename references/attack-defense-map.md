# 攻防对照：对手会怎么打，我们怎么防

站在攻击者的角度过一遍：他们用什么开源工具、按什么顺序、在日志里留下什么痕迹，每一步对应哪道盾。
体检时逐节对照；应急时用第 9 节的日志特征反查。
调研时间 2026-11-02，工具名和项目以 GitHub 当日页面为准，星数和版本会变，不作为判断依据。

## 2. 侦察：你以为藏起来的，对方都看得见

| 手法 | 原理 | 你的日志里 | 防守 |
|---|---|---|---|
| 子域名收集 | 证书透明度（crt.sh）+ 搜索引擎 + DNS 数据集 | 看不到，不访问你的服务器 | 别指望"子域名没人知道"；测试站、旧站要么下线要么同等加固 |
| 网络空间测绘 | FOFA、鹰图、Quake、Shodan 按网站图标哈希、标题、证书反查 | 偶尔有测绘爬虫取首页和 favicon | 没有 CDN 时查到的就是源站 IP；定期自己去这些平台搜一下自家图标和标题，看暴露了什么 |
| 备案关联 | 按企业名拉 ICP 备案、APP、公众号、小程序 | 看不到 | 备案主体名下的旧站、测试站会被一起找出来 |
| 从前端包抽接口 | JSFinder、LinkFinder、URLFinder、Packer-Fuzzer 从 JS 里提取所有接口路径，Packer-Fuzzer 还会自动测未授权和越权 | 先拉全部 .js，再把接口逐个请求一遍（11-01"逐个扫后台接口 6000 次"就是这个形态） | 接口路径藏不住，每个接口必须服务端鉴权；后台前端和官网分开打包；生产不发 sourcemap |
| 历史 URL | gau、waybackurls 从网页存档取历史地址 | 一批已下线的旧地址被请求 | 旧接口在服务端真正删除，不能只在前端隐藏 |
| 子域名接管 | 批量检查子域名的 DNS 记录是否指向已释放的资源（对象存储、CDN、第三方托管、被回收的 IP），抢注同名资源 | 看不到 | 下线资源先删 DNS 记录；体检时核对每条记录（`server-hardening.md` §9） |
| 拆客户端 | 反编译桌面客户端、解包小程序和 Electron，找内置密钥、数据库连接串、隐藏接口 | 看不到 | 客户端里没有秘密、不直连数据库（`permission-audit.md` §7.2） |

对我们最要紧：**接口和地址都藏不住，安全只能来自每个接口自己的鉴权和限速。** 后台入口可以额外做 IP 白名单或走 VPN，但这是加分项，不能替代鉴权。

## 3. 探测：扫描器的特征与对策

**会自报身份的工具**（默认 UA 子串，来自 Sigma 检测规则）：`sqlmap/`、`commix/`、`feroxbuster/`、`Fuzz Faster U Fool`（ffuf）、`gobuster/`、`Nikto`、`Nmap Scripting Engine`、`WhatWeb/`、`Wfuzz/`、`WPScan`、`zgrab/`。

**不自报身份的**：nuclei 默认随机浏览器 UA；自己写脚本的攻击者（11-01 就是）用 `python-requests`、`curl` 或伪造的浏览器 UA。**按 UA 封禁只能抓到最懒的那批。**

**更可靠的行为特征**

1. 请求与本站技术栈无关的路径：`.php`、`.jsp`、`/actuator`、`/wp-admin`、`/phpmyadmin`、`/cgi-bin`。ASP.NET 站点收到这些请求，几乎可以确定是扫描器。
2. 请求敏感文件：`/.git/config`、`/.env`、`/web.config`、`/appsettings.json`、`/elmah.axd`、`/trace.axd`、`*.map`、`/backup.zip`。
3. 短时间内大量不同路径，404 占比高。
4. 参数里出现带外回连域名：nuclei 默认的 interactsh 服务器 `oast.pro`、`oast.live`、`oast.site`、`oast.online`、`oast.fun`、`oast.me`，以及 `dnslog`、`burpcollaborator`、`ceye.io` 一类——说明对方在测 SSRF、命令注入、盲 XSS。
5. 同一个参数连续换几十种载荷（XSS / 注入扫描器的形态）。

**对策**

- **蜜罐路径**：上面第 2 条的路径，正常用户永远不会访问。命中一次就自动封禁（首次 1 小时，再犯递增），这是成本最低、误报最少的一条。注意 IIS 默认就会拦 `web.config`，要在应用层或 URL 重写里捕获才能记到。
- **行为评分自动封禁**：第 1、3、4 条按分数累计，超阈值封禁（设计见 `ip-ratelimit-blocking.md` §4.3）。
- **服务器出站白名单**：只放行支付、短信、微信、对象存储、AI 等必要地址。就算某处有 SSRF 或命令注入，带外回连也打不出去。
- 敏感文件本来就不该在网站目录里：配置放发布目录外或环境变量，`.git` 不上服务器。

## 4. 利用：常见手法与对应防线

| 手法 | 代表工具 / 资料 | 对策（详见） |
|---|---|---|
| SQL 注入 | sqlmap | 全部参数化（`input-files-outbound.md` §1） |
| XSS（尤其是存储型打后台员工） | dalfox、XSStrike（含盲 XSS 回调） | 白名单清洗 + 后台按纯文本展示 + CSP（§2） |
| SSRF | SSRFmap（含阿里云、AWS、GCE 元数据模块，以及 redis、mysql、`gopher://`） | 连接时拦内网 + 出站白名单（§4） |
| 命令注入 | commix | 不拼命令行字符串 |
| 隐藏参数 / 批量赋值 | Arjun（约 50～60 次请求试完 2.5 万个参数名） | 输入对象只收白名单字段，未知字段拒绝（`permission-audit.md` §2） |
| 令牌伪造 | jwt_tool（alg=none、算法混淆、弱密钥） | 固定算法白名单 + 强随机密钥；本项目用加密 Cookie，不用 JWT |
| 文件上传 | PayloadsAllTheThings「Upload Insecure Files」：SVG 里塞脚本、文件名 `../` 穿越、上传 `web.config`、NTFS `::$DATA`、空字节 | 系统生成文件名 + 扩展名白名单 + 上传目录禁止执行 + 禁止上传 `.config`（`input-files-outbound.md` §3） |
| IIS 短文件名枚举 | shortscan、IIS_shortname_Scanner（请求里大量 `~1` 和 `*`） | `fsutil behavior set disable8dot3 1`，再对网站目录 `fsutil 8dot3name strip`；请求筛选拦 `~`（`server-hardening.md`） |
| .NET 反序列化 | ysoserial.net | ASP.NET Core 没有 ViewState；.NET 9 起 BinaryFormatter 已移除；Json.NET 不开 `TypeNameHandling` |
| 借 machineKey / 会话密钥伪造登录态 | HackTricks IIS 清单 | 会话加密密钥目录限制权限、不进仓库、不进发布包 |
| Host 头注入 | 伪造 Host 让系统拼出指向攻击者域名的链接 | 生产配置 `AllowedHosts` 写死自己的域名；对外链接的域名从配置取，不从请求头取 |

## 5. 账号攻击

| 手法 | 工具 / 资源 | 日志特征 | 对策 |
|---|---|---|---|
| 在线爆破 | hydra、SecLists 字典 | 同一登录路径高频 POST，失败响应一样 | 账号×来源 + 来源级双维度计数，冷却递增（`auth-anti-abuse.md` §1） |
| 撞库 | OpenBullet2 + 泄露的账号密码 + 代理池 | **多 IP、低频，每个账号只试 1～3 次**——按 IP 限速抓不住 | 按账号统计跨 IP 的失败；后台陌生设备验证；异地登录提醒；可选：拦已泄露密码 |
| 识别图形验证码 | ddddocr（通用 OCR、滑块）、打码平台；svg-captcha-recognize 直接按字形识别 SVG 验证码，作者称 8.3 万次 100% 正确、每次不到 1 毫秒 | 验证码一请求就通过 | **图形验证码只是减速带**，挡不住有收益的黑产；关键动作（发短信）靠一次性凭证 + 多维限额 + 费用熔断 |
| 收集短信接口去轰炸别人 | SMSBoom 类项目维护几百上千个网站的发码接口模板（该项目 2024 年因"司法原因"归档）；黑产用爬虫批量收集企业网站的发码接口 | 大量不同手机号、请求参数固定可重放 | 发码前必须过验证，验证通过后服务端签发**绑定手机号的一次性凭证**；同号、同 IP、全站三重上限；只发国内号码 |
| 换 IP | proxy_pool（抓免费代理）、秒拨（家宽断线重拨，行业统计占黑产代理 IP 的九成以上） | 同一手机号或账号的请求来自大量不同 IP；家宽 IP 本身看着很正常 | **IP 只当弱信号**；限额同时按手机号、账号、设备、全站计；11-01 攻击 IP 是四川南充家宽并在同片区轮换，符合这一特征 |
| 盗会话 | 窃密木马偷浏览器 Cookie；Evilginx 类反向代理钓鱼页实时转发密码和二次验证 | 后台会话从陌生 IP 继续使用，没有对应的登录记录 | 高危操作当场重新验证；高权限账号用通行密钥；会话突变告警（`auth-anti-abuse.md` §1） |
| 冒充客户找客服 | 社工话术："手机丢了，帮我换个号" | 看不到，只在工单里 | 客服只发起不生效、核验、通知原手机、冷静期（`auth-anti-abuse.md` §4） |
| 批量注册 | 卡商 → 猫池 → 接码平台；虚商号段（162、165、167、170、171）和物联网卡（146）是历史上的黑卡主力 | 注册时间密集、号码连号或集中在少数号段 | 号段分风险等级（只做加强校验，不一刀切拒绝）；新号注册当天不发券、不计返佣；注册聚集告警 |

## 6. 业务逻辑：最容易被忽略、最直接要钱

**并发竞争**（Turbo Intruder 的"单包攻击"：HTTP/2 下把二三十个请求塞进一个 TCP 包，到达时间差约 1 毫秒）。能用来：重复兑换卡密、重复使用优惠券、一个邀请码注册多个号、绕过限流、重复使用验证码。

- 对策：凡是"先查、再扣"的和钱有关的操作，在**一条 SQL** 里完成（带余量条件的 `UPDATE ... WHERE 剩余 > 0`，看影响行数），或事务 + 行锁 + 唯一约束兜底。
- 正面示例（参考项目的公开领券）：总量用一条 `UPDATE ... WHERE ClaimedCount < TotalQuota` 原子扣减；"每人一张"对（用户, 活动）加范围锁；挂账用唯一索引兜底。
- 验收：写一个并发测试，同一请求同时发 20 次，确认只成功一次。

**越权**（Autorize、国产 xia_Yue：用低权限或未登录的身份重放高权限请求，比对响应）。对策见 `permission-audit.md` §2；体检时自己也这样测一遍。

**OWASP 自动化威胁（OAT）对照**

| 编号 | 威胁 | 这类网站的场景 | 主要防线 |
|---|---|---|---|
| OAT-002 | 令牌破解 | 卡密、券码、邀请码、分享令牌被枚举 | 令牌 ≥ 128 位随机；错误次数按用户限速 |
| OAT-007 / 008 | 撞库 / 凭证填充 | 会员、代理登录 | 盾 3 |
| OAT-009 | 验证码破解 | 打码平台、OCR | 验证码只当减速带，盾 4 |
| OAT-011 | 爬取 | 文章、价格、客户数据被爬 | 分页上限、ID 不可枚举、归属鉴权 |
| OAT-012 | 套现 | 盗号后提现、代理返佣提现 | 提现二次验证、延迟到账、人工审核阈值 |
| OAT-014 | 漏洞扫描 | 第 3 节 | 蜜罐路径 + 自动封禁 |
| OAT-015 | 拒绝服务 | CC 攻击；流量型攻击把源站打进黑洞 | 全站频率兜底，盾 2；黑洞预案与高防（`server-hardening.md` §10） |
| OAT-016 | 数据歪曲 | 刷统计、刷推广数据 | 统计口径排除异常来源 |
| OAT-017 | 灌水 | 反馈、工单、评论 | 提交限速 |
| OAT-019 | 批量注册 | 11-01 的 65 个垃圾号 | 盾 4 + 注册聚集告警 |
| OAT-021 | 占库存 | 下单不付款占住名额；**领券链接被批量乱填刷光总量** | 待支付超时释放；限量资源按 IP / 设备限速 |

**薅羊毛**：批量注册领新人券、同一邀请码刷返佣。对策：奖励在被邀请人**实际付费并过了退款期**之后再发；同设备、同 IP、同支付账户、同微信之间的邀请关系不计奖励；每个邀请人设每日上限。

## 7. AI 驱动的攻击：速度和广度都变了

- HexStrike AI 用 MCP 编排 150 多个安全工具，2025-08 Citrix 漏洞披露后 12 小时内地下论坛就在讨论用它扫描利用。
- Anthropic 2025-11 报告：攻击者把 Claude Code 当执行体，AI 完成了 80～90% 的战术操作，峰值每秒多次请求。
- Strix、Shannon、PentAGI、PentestGPT 等开源项目，配一个大模型 API 密钥就能跑"写脚本 → 运行 → 读结果 → 下一步"的自动化渗透。

对防守的影响：

1. "没人知道这个地址""这个接口前端没调用"都不再是防线。
2. 漏洞从披露到被扫，窗口按小时算：依赖和框架出高危公告，24 小时内评估，72 小时内修补。
3. 低水平攻击者也能做逐项验证式的深度测试，**发现和处置也必须自动化**：自动封禁 + 实时告警。
4. AI 生成的探测往往带着"可回收的标记"（自定义 UA、固定前缀的测试账号、`probe` 字样的探针文件）。可以做成告警规则，但下次一定会变，根本还是按行为防。

|---|---|---|

| 目标：盗号 | 撞库、找回密码 | 双维度锁定、后台二次验证 |
| 目标：薅羊毛 | 新人券、邀请返佣、试用 | 延迟发放、关联识别、原子扣减 |
| 目标：短信轰炸 | 收录你的发码接口 | 一次性凭证 + 三重限额 + 费用熔断 |
| 目标：爬数据 | 遍历 ID、翻页 | 归属鉴权、分页上限、ID 不可枚举 |
| 目标：入侵勒索 | 上传、弱口令、暴露端口 | 上传隔离、端口收口、出站白名单、离线备份 |

## 9. 日志特征速查（应急时反查）

| 看到什么 | 说明什么 | 做什么 |
|---|---|---|
| UA 含 `sqlmap/`、`Nikto`、`feroxbuster/`、`Fuzz Faster U Fool`、`gobuster/`、`WPScan`、`zgrab/`、`Nmap Scripting Engine` | 现成扫描工具，没改默认 UA | 直接封禁 |
| UA 是 `python-requests/*`、`curl/*`、`Python-urllib/*`、`Go-http-client/*` 且量大 | 自己写的脚本 | 看路径分布判断意图 |
| `.php`、`.jsp`、`/actuator`、`/wp-*` 出现在 ASP.NET 站 | 通用漏洞扫描 | 封禁 |
| `/.git/config`、`/.env`、`/web.config`、`/appsettings.json`、`*.map`、`elmah.axd`、`trace.axd` | 敏感文件探测 | 蜜罐封禁；核对是否有 200 |
| 路径里有 `~1`、`*` | IIS 短文件名枚举 | 检查 8.3 短文件名是否已关 |
| 参数里有 `oast.*`、`dnslog`、`burpcollaborator`、`ceye.io` | 在测 SSRF / 命令注入 / 盲 XSS | 查这些请求的返回；确认出站白名单 |
| 同一参数连续几十种 `<script`、`onerror`、`' OR`、`../` 变体 | XSS / 注入扫描器 | 确认是否存储进库、后台展示是否转义 |
| 登录接口失败，来自很多 IP、每个账号只试一两次 | 撞库 | 按账号跨 IP 统计；通知受影响用户改密 |
| 发短信接口：很多不同号码、请求参数固定 | 被收录进短信轰炸 | 立即收紧同 IP 和全站上限；升级验证 |
| 同一 Cookie 在同一毫秒发出多个相同请求 | 并发竞争攻击 | 查对应操作是否原子 |
| 网关、模型接口的用量突增 | 钱包耗尽 / 额度被盗刷 | 暂停网关、查是哪些账号、吊销 token |

`scripts/log_triage.py` 已内置上面大部分特征。

## 10. 以攻验防：用对手的工具检查自己

**规矩**：只扫自己的资产；优先扫测试环境；扫生产要限速、不开侵入式检测、提前把扫描机 IP 加进封禁白名单；结果和上一次对比，只看变化。

| 工具 | 做什么 | 频率 |
|---|---|---|
| OWASP ZAP baseline（Docker） | 爬 1 分钟后被动扫描，不发攻击；退出码可当发版门禁 | 每次发版扫测试环境 |
| nuclei | 用社区模板扫暴露面、已知漏洞、错误配置 | 每月一次 |
| MDN HTTP Observatory | 响应头评分（不查 TLS），有 API | 每次发版后 |
| testssl.sh | TLS 配置、证书 | 每次换证书后 |
| shortscan | 自查 IIS 短文件名是否还能被枚举 | 改完服务器配置后 |
| 自写并发测试 | 同一请求并发 20 次，确认钱相关操作只成功一次 | 改到相关代码时 |
| 双账号越权测试 | A 的资源 ID 用 B 的身份请求 | 每个新接口 |
| 去 FOFA / 鹰图搜自家图标和标题 | 看外界能找到你的哪些站和端口 | 每季度 |
| 授权前提下用开源 AI 渗透代理扫测试环境 | 用攻击者的方式找问题 | 可选，每季度 |
