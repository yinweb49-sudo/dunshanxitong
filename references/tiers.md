# 防护档位：按项目价值定防护深度

不是每个项目都要十四道盾拉满。一个内部小工具照收钱的业务系统的标准做，几周工期换来的是几乎不存在的风险；反过来，一个收钱的系统只做保底，被刷一次的损失就超过全部安防投入。

防护深度由两个维度决定：

- **档位**（四档）：按"出事最坏会怎样"和"有多少人想打你"定，决定通用防线做多深——主机、监测、运维流程、后台账号保护、档案详细程度。
- **专项**（按功能）：项目有某个功能，这个功能对应的硬项就必须做，**与档位无关**。发短信接口被收录进轰炸工具只要几天，一个保底档的小站照样会被刷光短信费。

清单（`baseline-checklist.md`）每一项都标了档位，意思是"从这一档起必做"；专项分组只在项目有对应功能时适用，适用后同样按档位列执行。

## 1. 定档

逐行回答，**取命中的最高档**。

| 问题 | 一档 保底 | 二档 基础 | 三档 正常 | 四档 极度 |
|---|---|---|---|---|
| 谁在用 | 内部员工、受邀的少数人 | 对外开放注册 | 对外注册，用户成规模（参考 ≥ 1 万） | 大规模（参考 ≥ 100 万），或面向公众的基础服务 |
| 钱 | 不涉及 | 只有简单在线支付（付款即发货，没有余额） | 余额、金币、积分可兑现；优惠券、邀请返佣、免费额度；代理分佣 | 提现、资金撮合、金融类；单笔或日流水大 |
| 个人信息 | 几乎没有 | 手机号、昵称 | 成规模的手机号、地址、订单、聊天记录 | 身份证、银行卡、健康、精确位置、未成年人信息成规模 |
| 付费资源 | 无 | 少量（如只在登录时发短信） | 短信、AI、第三方计费接口对外开放 | — |
| 停机代价 | 停一天无所谓 | 影响体验 | 直接影响营收、客户投诉 | 停机即重大损失或社会影响 |
| 被盯上 | 没有 | 偶发扫描 | 被有收益动机的黑产打过，或行业是黑产热门（电商、营销工具、游戏、教育、金融） | 被持续定向攻击 |
| 合规 | — | — | 要评估等保定级 | 等保三级、关键信息基础设施、行业强监管 |

- 参考数字只帮助判断，不是硬杠；拿不准时选高一档。
- 定档结论写进安防档案第 0 节，写清命中了哪几行。用户可以改档，改低时在档案"已知风险与接受记录"里留一条。
- 示例：参考项目有余额金币、营销奖励，对外开放短信和 AI，被黑产打过 → 三档 正常（见 `examples/示例项目-安防档案.md`）。

## 2. 各档施工目标

### 一档 保底

- **适合**：内部工具、演示站、活动页、原型、个人项目。
- **目标**：不当"最低垂的果子"——扫描器顺手拿不下，密钥不外泄，后台不被爆破，删库能恢复。
- **施工**：清单里标"保"的项；公共件只建三样：接口默认需要登录、取访客 IP 的唯一方法、登录失败冷却。
- **档案**：简版，只填第 0 节定档、第 1 节基本信息、第 4 节里标"保"的项。
- **不做**：封禁名单、自动封禁、蜜罐、陌生设备验证、出站收口、每日摘要、以攻验防、完整档案。
- **参考工作量**：熟悉代码的一个人半天到一天。

### 二档 基础

- **适合**：对外开放注册、有用户数据但不涉及资金或只有简单支付的网站，小程序后端，SaaS 早期。
- **目标**：账号刷不动、数据不越权、被打的时候有人知道。
- **施工**：保底 + 标"基"的项；模式 A 的公共件全部建好（封禁名单和蜜罐除外）；告警推到群机器人；应急手册就位。
- **档案**：完整档案，匿名接口表必填。
- **参考工作量**：2～5 天。

### 三档 正常

- **适合**：有资金流、营销奖励、对外开放付费资源、成规模个人信息、员工后台多入口的业务系统。
- **目标**：攻击者刷不到钱、刷不到资源、进不了后台；出事 15 分钟内知道、1 小时内止血；任何一次攻击都能拿证据复盘。
- **施工**：基础 + 标"正"的项。重点是封禁名单 + 自动封禁 + 蜜罐、后台陌生设备验证、业务限额表、出站收口、云操作审计、主机入侵发现、每月以攻验防、黑洞预案。
- **档案**：完整档案 + 业务限额表 + 出站连接清单 + DNS 与云账号清单。
- **参考工作量**：首次 1～3 周；之后每月固定半天例行（看告警汇总、扫描结果、依赖公告）。

### 四档 极度

- **适合**：金融、提现、敏感个人信息大户、等保三级、被持续定向攻击。
- **目标**：假设任意一层已被突破，仍能发现、限制损失、追溯到人。
- **施工**：正常 + 标"极"的项。常态接入高防或 CDN、隐藏源站；后台只经 VPN 或零信任网关；超管和财务用通行密钥；敏感字段加密；每年外部渗透测试和应急演练；7×24 告警响应；等保测评。
- **说明**：这一档靠一个 AI skill 做不完，要有专人或外部安全服务。skill 负责代码层、档案和例行检查。

## 4. 升档与复核

出现以下任何一条，当场重新定档：

- 接入支付、余额、营销奖励、提现；
- 把短信、AI 等付费资源开放给外部用户；
- 开始存身份证、银行卡等敏感个人信息；
- 外部注册用户跨过参考规模；
- 被有收益动机的攻击者打过一次（至少到正常档）。

模式 B 体检时先复核档位；模式 C 写新功能时，先看它有没有触发专项或升档；模式 D 处置完重新定档。
降档只在相关功能下线后做，并在档案变更记录里写明。

## 5. 不随档位变的东西

- 红线（`SKILL.md`）对所有档位生效。
- 专项的必做项与档位无关。
- 打扰度约束：档位越高，多的是后台检测和流程，不是让正常用户多点几下。
- 已经做好的高档防护不拆。
