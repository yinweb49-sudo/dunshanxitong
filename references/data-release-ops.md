# 第 11 道盾：生产数据与发版

攻击者能造成的损失，往往不如自己人手滑大。这一道盾防的是"误操作"和"出事回不去"。

## 1. 生产库铁律

1. 本地开发默认连测试库（生产快照），连接串放 user-secrets / 环境变量，不进代码、不进发布包以外的任何地方。
2. 未经负责人当次同意，不对生产库做结构变更，不改不删生产数据。
3. 大改动流程：测试库开发验证 → 负责人批准 → 备份 → 生产执行 → 回读核实。
4. 与其他程序共享的老表，只能在末尾追加可空列，不改列名、类型、列序。

## 2. 生产库只读核对

需要在本地看线上最新数据时，不能用普通方式直连。参考项目的做法是三层保护（实现见 `dotnet-patterns.md` §12）：

- 启动脚本只在子进程里临时注入生产连接串，不改 user-secrets，不改配置文件，进程退出即失效。
- 应用层：只允许开发环境开启；后台任务和启动种子全部不挂；HTTP 只放行 GET / HEAD / OPTIONS 和后台登录登出；响应头带模式标记，启动脚本据此确认进了只读模式。
- 数据库命令层：拦截写语句、存储过程、加锁读。
- 用完必须切回测试库。

**更进一步（建议）**：给只读核对、报表、数据分析单独建一个只有 SELECT 权限的数据库账号。应用层拦截是"自律"，数据库权限才是"他律"。

## 3. 迁移执行器

参考项目迁移执行器的护栏，可直接照搬：

- 只能执行迁移目录内、文件名形如 `001_name.sql` 的文件。
- 执行前打印目标服务器和库名。
- 识别出目标是生产库（按服务器地址、库名匹配）时，没带 `-AllowProd` 开关直接拒绝——逼执行人"显式确认打的是生产库"。
- 按 `GO` 切批，每批有超时，失败即停。
- 迁移 SQL 一律幂等（`IF NOT EXISTS` / `WHERE NOT EXISTS`），已执行的不改号不改内容。

**建议补强**

- 每个迁移文件自带事务：开头 `SET XACT_ABORT ON; BEGIN TRAN;`，结尾 `COMMIT;`（含 DDL 的批次注意 SQL Server 对部分语句的事务限制）。否则中途失败会留下执行了一半的状态。
- 生产识别除了字符串匹配，再加一道"库里查标记"：在生产库的配置表里放 `environment = production`，执行器连上后先查它。生产库搬家、改名都不会漏判。
- 执行器记录每个迁移的执行时间、执行人、目标库（迁移历史表）。

## 4. 备份

| 类型 | 用途 | 要求 |
|---|---|---|
| 物理备份（.bak / 快照） | 灾难恢复 | 数据库服务器上定时自动做（全量 + 差异 / 日志），保留策略写进档案 |
| 逻辑导出（bacpac / dump） | 大改动前的兜底快照，导成旁库后人工修复 | 改表、批量改数据、上迁移前手动做一次 |
| 异地 / 离线副本 | 防勒索、防机房事故、防误删备份 | 至少一份不在生产服务器、不在同一账号下；正常档起至少一份**生产服务器上的凭据删不掉、改不了**（对象存储开防删除或版本保留、离线介质）——勒索软件进来后第一件事就是删它能碰到的备份 |

- 备份文件本身就是全量敏感数据：加密存放（BitLocker、7z AES、云存储服务端加密），别散落在开发机仓库目录里。案例：一台开发机上翻出过 19 个未加密的全量导出文件。
- 导出时连接串别放在命令行参数里（进程列表能看到），改用环境变量或配置文件。
- **定期做恢复演练**：没恢复过的备份不算备份。演练记录写进档案。
- 删除攻击数据这类"小范围清理"用 `scripts/purge_with_backup.ps1`，每次删除前导出 JSON。

## 5. 发版

参考项目发版流程里值得照搬的护栏：

1. **出包闸门**：打正式域名的包时，校验包内生产配置指向正确的库，不对就中止，且不回显凭证。
2. **剔除**：开发配置、密钥目录、日志、调试符号（pdb）、本地缓存、种子密码文件、`.git`、业务 sourcemap。
3. **敏感值不进包**：签名私钥放应用池环境变量，渲染令牌放机器环境变量；脚本只检查"有没有、格式对不对"，不回显值。
4. **删除护栏**：发版脚本里的删除只能删允许目录内部，拒绝删目录本身、拒绝过短路径。
5. **上传核验**：上传后回读远端文件大小。建议再比对 SHA-256，防止传输损坏或被替换。
6. **替换与回滚**：停应用池 → 等进程退出（超时强杀）→ 旧版改名备份 → 解压新版 → 启动；任何一步失败自动改回旧版并启动；验收不过手动回滚。保留最近 2 个旧版。
7. **先迁移后发版**：有迁移时先在生产执行并核实，再发程序。
8. **发版台账**：版本代号、提交号、迁移、备份文件名、验收结果。
9. **正式发版前**：本地起前后端给负责人肉眼确认；涉及迁移先做数据库备份；提交前搜一遍 `.pfx`、`secret`、`password` 等。

**建议补强**

- 生产连接串不随包发：放在服务器上的环境变量或包外的独立配置文件，发布包里不带任何生产密码。这样开发机上堆着的发布包、传输过程都不会泄露数据库密码。
- 发布包用完就删，或移到加密目录；仓库根目录不堆含生产配置的压缩包。
- 想去掉停机窗口：IIS 用两个目录轮换 + 切换物理路径，或前面加反向代理做蓝绿切换。

## 6. 代码仓库与依赖

- 仓库私有；能放私网就放私网（WireGuard），公网打不开是设计如此，不为"能连上"开放端口或关掉 TLS / 主机密钥校验。
- 凭据放系统凭据管理器，不内嵌在 remote URL 里。
- `.gitignore` 至少挡：`.env*`、生产配置、本地配置、密钥目录、证书与私钥、数据库备份、发布包、含测试账号的脚本、AI 助手的本地配置。
- 定期扫历史：`gitleaks detect` 或 `git log -p | grep` 常见密钥特征。已经进过历史的密钥视为泄露，轮换。
- 入库的公共配置里也不放第三方 token（案例：入库的 `appsettings.json` 里有 IP 归属地服务的 token 明文）。
- 依赖防投毒、漏洞扫描、开发机与 AI 编程助手的护栏，见 `dev-supply-chain.md`。
