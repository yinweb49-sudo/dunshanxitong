# 第 9 道盾：权限、越权与审计

11-01 攻击方逐个扫了 6000 多次后台接口，全部 401 / 404。能做到这一点，靠的是"每个后台接口默认要登录 + 权限点"。

## 1. 权限模型

1. 员工后台用角色 + 权限点：员工 → 角色（可停用）→ 权限点代码，多角色取并集。权限缓存（如 10 分钟），角色或授权变更时立即全部失效。
2. **每个后台接口都声明权限点**，默认拒绝。参考项目有 194 个权限码、698 处接口级声明。没有声明的接口要在审查时说明原因（如"只要登录、由服务层判断是不是本人"）。
3. 无权限返回 403 和统一错误码，并单独记一条"权限拒绝"审计——有人在批量试接口时这里会突增。
4. 前端菜单和按钮按权限显隐只是体验，后端必须再校验。前端路由没有权限守卫时，直接输地址能看到页面壳，但数据接口要拦住。
5. 敏感权限（看完整联系方式、看凭证明文、退款、改权限、封禁、导出）单独设权限点，不和"能进这个页面"绑在一起。
6. 超级管理员专属操作（IP 封禁、角色授权）只授给超级管理员角色。
7. 合作方后台（代理、服务商）单账号无角色时，也要每个请求校验账号仍有效。
8. **默认需要登录，公开的逐个标出来**。ASP.NET Core 不设兜底策略时，没写 `[Authorize]` 的接口对所有人开放——新写一个控制器忘了标，就是一个公开口子。开工时就设兜底策略：
   ```csharp
   builder.Services.AddAuthorization(o =>
       o.FallbackPolicy = new AuthorizationPolicyBuilder(/* 列出所有认证方案 */)
           .RequireAuthenticatedUser().Build());
   ```
   公开接口（登录、注册、回调、公开页面）显式标 `[AllowAnonymous]`。老项目要加时先列出全部受影响的接口再改，避免把公开页面误关。
9. 自定义令牌（如桌面客户端的 Bearer token）做成正式的认证方案，挂在框架的认证管道里，不要在每个方法里手动解析——漏写一处就是一个未鉴权接口。
10. 体检时自动列出"所有匿名可访问的接口"（没有 `[Authorize]` 或显式 `[AllowAnonymous]` 的），逐个核对限速和返回内容，结果写进安防档案的匿名接口表。

## 2. 越权（IDOR）

1. **身份只从登录态取**：会员 ID、合作方 ID 一律从登录凭证里取，接口不接收前端传的 `uid`、`channelId`。
2. **每个查询都带归属过滤**：`WHERE Id = @id AND OwnerId = @me`。查不到和不属于你返回同一个"不存在"，不区分。
3. 列表查询里，前端传的归属条件要被服务端强制覆盖。
4. 合作方看客户：先确认"这个客户绑定在我名下"，不是就 403。
5. 员工端的数据范围（只看自己名下、主管看团队、有权限看全部）在服务层写清楚，同一业务的所有入口共用一个判断。设计上允许的横向可见（比如客服按关键字能搜到别人名下的客户）要在档案里写明。
6. 不把请求体直接绑定到数据库实体：用专门的输入对象，只接收允许修改的字段，防止多传 `Status`、`Amount`、`OwnerId` 改掉不该改的东西。
7. 匿名可访问的分享链接、付款页用安全随机令牌或签名令牌，有有效期；令牌对应的资源只读。
8. 开发、模拟到账类接口只在纯本地开发环境注册，生产环境 404。
9. **返回字段最小化**（属性级授权）：接口只返回调用方有权看、页面确实要用的字段。前端遮挡不算，接口返回了完整手机号就等于泄露了。
10. 匿名接口的返回不能成为"查询器"：不同结果的提示和返回结构不要暴露"这个账号存在""这个号码注册过"。案例：公开领券接口填手机号时返回"已到账"或"挂账待注册"，填账号不存在时提示"没有找到这个账号"——匿名、不限速，等于一个可以批量查询的账号和号码字典。

体检时抽查方法：用 A 账号拿到一个资源 ID，换 B 账号请求；用低权限员工直接调高权限接口；在请求体里多传几个敏感字段；对匿名接口批量换输入，看返回能不能区分出账号或号码是否存在。攻击者有现成工具做这件事（Autorize、xia_Yue：自动用低权限或未登录身份重放请求并比对响应）。

## 2.5 业务流程完整性

1. **业务限额写成文档**：每类有限资源（券、名额、返佣、免费额度、短信、AI 调用）按用户、按全站各有多少上限，写进安防档案的业务限额表，代码照表实现。
2. **步骤不能跳**：多步流程（下单 → 支付 → 发货，验证 → 绑定 → 登录）的每一步由服务端校验前一步已完成，不信任前端传的"当前步骤"。
3. **并发安全**：和钱、名额、库存有关的"先查再扣"在一条 SQL 里完成（带条件的 `UPDATE`，看影响行数），或事务 + 行锁 + 唯一约束。攻击者用"单包攻击"能让几十个请求在 1 毫秒内同时到达。正面示例：公开领券总量用一条 `UPDATE ... WHERE ClaimedCount < TotalQuota` 原子扣减，"每人一张"加范围锁，挂账用唯一索引兜底。
4. **幂等**：支付到账、发放权益、发通知都按业务唯一键去重，重复请求返回第一次的结果。
5. **高价值操作多人审批**：大额退款、批量改价、批量发券、导出全量客户数据，设金额或数量阈值，超过要第二个人批准。
6. **限量资源的匿名入口要限速**：不需要登录就能消耗的资源（公开领券、试用申请、预约名额），按 IP 和设备限速，否则会被批量乱填刷光（OWASP 自动化威胁 OAT-021 占库存）。

## 2.6 资产清单

- 列出所有对外的站点、端口、接口版本、调试端点、文档页（Swagger）、测试账号，写进安防档案。
- 下线的接口在服务端真正删除，不能只是前端不再调用：攻击者会从历史网页存档和旧版前端包里把老接口挖出来。
- 每季度从外部视角核对一次（见 `attack-defense-map.md` §10）。

## 3. 审计

1. 高风险操作（删除、退款、改金额、改权限、重置密码、封禁、查看凭证明文、导出、改配置）**必须**留审计。参考项目有 418 处审计声明，其中 112 处高风险。
2. 记录：操作人、模块、动作、路径、目标对象、脱敏后的请求参数、IP、UA、成功与否、错误信息；高风险操作另存修改前后快照。
3. 审计日志只开查询接口，没有删改接口；数据库账号层面最好也不给应用删除审计表的权限。
4. 审计里的敏感字段按字段名脱敏，脱敏名单覆盖所有密钥类字段（见 `money-secrets.md` §2）。
5. 只读核对模式下不写审计。

## 4. 高风险操作的交互

- 二次确认，写清后果（"解封后该 IP 立即可以访问"）。
- 防误操作的硬拦截在后端也做一遍（不能封自己当前的 IP、不能删除最后一个超级管理员）。
- 批量操作有数量上限，超过要分批或走审批。

## 5. 多入口一致性

同一业务可能有电脑端、手机端、桌面客户端、合作方后台、官网、旧系统多个入口。

1. 改金额口径、数量换算、权限、校验、状态、默认值、请求字段时，先列出这个接口 / 服务的全部调用入口，逐个确认。
2. 后端不能用"新字段可选 + 缺了就走旧口径"静默兼容没升级的入口。要么所有入口一起升级，要么后端明确拒绝旧请求。
3. 安全规则同理：注册校验、登录风控、限速、"能不能登录"判断，每个入口都要生效。代理后台没接入登录风控、旧官网注册不验短信，都是"某个入口漏了"。
4. 交付时每个入口都回归一遍；某个入口确认不适用，写明原因。

## 6. 服务账号与开放 API

- 服务账号（内部自动化）：API Key 只存哈希，不签发 Cookie，永远不能登录后台界面；只挂在需要的接口上；按账号限流；调用方 IP 记日志。
- 开放 API（给客户用）：每个用户密钥数量上限；按用户（所有密钥合计）限流，超限 429 并带重试时间；鉴权处理器只认指定路径前缀，并校验用户是否被禁用；结果文件走签名链接。
- 内部健康检查接口：不要匿名开放会消耗资源的检查（启动浏览器、查库），也不要返回磁盘路径和异常原文。对外的探活只回 `ok`，详细自检放在需要登录的接口或只允许本机访问。

## 7. 实时通道与客户端【专项】

### 7.1 实时通道（WebSocket / SignalR）

1. **握手时鉴权**：连接建立时验证登录态，未登录拒绝连接。SignalR 的 Hub 同样受兜底授权策略约束，匿名 Hub 要显式标注并列进匿名接口表。
2. **校验来源**：WebSocket 不受同源策略限制，浏览器会自动带上 Cookie。别的网站的页面可以用访客的身份连上你的 WebSocket 并收发消息（跨站 WebSocket 劫持）。握手时校验 `Origin` 在白名单内。
3. **每条消息按权限校验**：不能只在连接时校验一次。每个 Hub 方法和权限点对应；订阅某个对象的推送（某张订单、某个群）时校验归属。
4. 每个账号的连接数和每秒消息数有上限；单条消息大小有上限。
5. 账号被禁用、强制下线时，服务端主动断开它的连接。

### 7.2 发到用户手里的程序

桌面客户端、App、小程序、前端包，发出去就会被拆开看：.NET 程序用 dnSpy / ILSpy 能直接还原源码，Electron 的 `app.asar` 解包即得 JS，小程序包能被反编译，App 能被抓包和脱壳。

1. **客户端里没有秘密**：不内置数据库连接串、平台 API 密钥、签名私钥、对象存储永久密钥、管理员接口地址加口令。需要访问云资源的，由服务端签发短时、限定范围的临时凭证。
2. **客户端不直连数据库**：直连等于把数据库账号发给每个用户，任何人都能绕过所有业务校验读写整个库。一律改成经服务端接口。
3. **所有校验和计价在服务端**：客户端的校验只是体验。客户端和服务端之间的请求签名只能防传输被篡改，证明不了"请求来自你的客户端"——签名算法和密钥都在客户端里。
4. **自动更新是供应链**：更新包做代码签名（或用写死在客户端里的公钥验签），HTTPS 下载，验签失败不安装；更新服务器和发布目录的写权限按生产服务器对待。更新通道被拿下，等于所有客户电脑被拿下。
5. Electron：`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`；不在有 Node 权限的窗口里加载远程页面；`shell.openExternal` 只放行 http/https。
6. 小程序：`session_key` 只在服务端，不下发前端；登录用 `code` 到服务端换身份；加密数据在服务端解密。
7. 登录 token 放在系统提供的安全存储（Windows 凭据管理器 / DPAPI、Keychain、Keystore），不放明文配置文件。
