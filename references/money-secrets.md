# 第 8、10 道盾：资金与回调、密钥与敏感数据

## 1. 资金与支付回调

### 1.1 下单

1. 价格、优惠、数量、加价全部在后端按商品配置计算。前端传来的金额只用于"和后端算的对一下，不一致就提示刷新"，绝不作为入账依据。
2. 同一业务的多个下单入口（电脑端、手机端、客户端、代理端）共用一个计价服务，口径一致。
3. 订单号、支付单号由服务端生成，带业务前缀，回调时按前缀分到对应的到账支路。
4. 案例：攻击号下了 999999 金币 9999.99 元的订单、填了优惠券编号 1，都只是待支付状态，没有产生任何权益。

### 1.2 支付回调（以微信支付 APIv3 为例，其他渠道同理）

参考项目的线上实现，可整套照搬：

| 环节 | 做法 |
|---|---|
| 入口 | 新旧回调地址都只是薄壳，调同一个处理入口；请求体上限 256KB |
| 配置自检 | 启动时检查：APIv3 密钥 32 字节、时间窗 60～900 秒、回调地址必须 HTTPS、私钥和平台公钥 ≥ 2048 位；日志不打印密钥 |
| 验签 | 对 `时间戳\n随机串\n报文\n` 做 RSA-SHA256 校验；按证书序列号选平台公钥；时间戳超出时间窗拒绝；各请求头有长度上限 |
| 解密 | 只接受 AEAD_AES_256_GCM，用 APIv3 密钥解密 |
| 报文核对 | 应用 ID、商户号与本地配置一致；交易状态成功；金额 > 0；币种人民币；支付时间不晚于当前时间 + 时间窗 |
| 金额核对 | 本地订单金额换算成分后必须与回调金额严格相等；订单号严格相等 |
| 防重放 | 按通知 ID 去重：同 ID 同报文的并发请求合并等待；同 ID 不同报文直接拒绝；处理失败立即释放，让平台重试 |
| 幂等到账 | 事务内先按平台交易号加范围锁（同一交易号不能绑两张单），再锁订单行；已支付且交易号相同直接返回成功；交易号不同拒绝；只有"待支付 → 已支付"这一次跃迁才发放权益 |
| 数据库兜底 | 平台交易号、商户订单号建唯一索引 |
| 类型约束 | "核对过的支付"是一个只能由核对逻辑构造的类型，到账服务拿不到裸订单号字符串 |
| 查单兜底 | 前端轮询或定时任务主动查单，和回调走同一个到账入口 |

**注意**：验签必须是强制的。参考项目的实现在"没配平台公钥"时会退化为不验签的兼容模式，只靠 APIv3 密钥解密保证真实性。上线检查清单里要有"平台公钥已配置、日志显示验签已启用"一项。

### 1.3 其他回调（公众号、第三方事件）

- 签名校验用常数时间比较；能开安全模式（报文加密）就开，报文里没有加密节点就拒绝；解密后核对应用 ID。
- 请求体上限；验签失败不写任何业务数据。
- 重复投递按事件唯一键去重。
- OAuth：`state` 用安全随机数，服务端存用途和回跳地址，5 分钟有效、一次性；同时种一个浏览器绑定 Cookie，回调时与 `state` 比对，防登录 CSRF；回跳地址只存服务端、只允许站内路径。

### 1.4 退款与资金调整

- 退款只有一个入口（存储过程或服务），所有界面都调它，不在别处重写规则。
- 按金额或时效分级授权（如普通权限只能退 3 天内的单），高风险审计。
- 余额、金币、额度的增减都有流水，流水与余额同一事务。
- 例外通道（特批退款）单独建、单独授权、只从一个后台触发。

### 1.5 营销与奖励（防薅羊毛）

黑产的完整链条：卡商 / 接码平台供号 → 批量注册领新人券 → 连号带券转卖；或者用同一个邀请码批量注册刷返佣。

1. **奖励延迟发放**：邀请返佣、新人奖励在被邀请人**实际付费并过了退款期**之后再结算，不在注册时发。
2. **关联去重**：同设备、同 IP 段、同支付账户、同微信、同号段连号之间的邀请关系不计奖励。
3. **每个邀请人设每日上限**，超过进人工审核。
4. 免费额度（试用期、AI 免费次数）同样是"奖励"：每个新号都有一份，批量注册就等于批量领钱，额度要小，并和注册风控挂钩。
5. 套现（OAT-012）：提现、返佣到账设二次验证、延迟到账、超阈值人工审核。

### 1.6 防枚举的令牌

卡密、券码、邀请码、分享链接令牌、领取链接令牌，都可能被批量猜（OWASP 自动化威胁 OAT-002）。

- 用安全随机数生成，至少 128 位熵（32 位十六进制或 26 位 36 进制）。
- 输错按用户、按 IP 限速；连续输错多次要求验证码。
- 历史遗留的短卡密（12 位以内）单独评估：如果仍有效，加严限速或批量换新。

## 2. 密钥存放

| 类型 | 放哪里 | 不放哪里 |
|---|---|---|
| 本地开发连接串、密钥 | user-secrets / 本地 `.env`（被 .gitignore 挡） | 代码、入库的配置文件 |
| 生产连接串 | 服务器环境变量或包外的配置文件 | 代码仓库；最好也不进发布包 |
| 签名私钥、渲染令牌 | 应用池 / 机器环境变量 | 配置文件、数据库 |
| 运行时要能在后台改的第三方密钥（短信、支付、对象存储、AI） | 数据库配置表，后台只显示"已配置 / 未配置"，修改时审计里只记"已修改" | 日志、审计快照、接口返回 |
| 加密用的主密钥 | 与密文分开存放：环境变量、云厂商密钥管理服务 | 与密文同一个库同一张表 |

- 判断"是不是密钥"的规则要覆盖全部密钥名。案例：配置列表按名字后缀识别密钥（`.secretKey`、`.apiKey` 等），店铺凭证的加密主密钥名字不符合这些后缀，结果在后台配置列表里明文可见，修改时还会明文写进审计快照——而且它和密文在同一个库。
- 入库的公共配置文件里也不能有第三方 token。
- 密钥轮换：档案里写清每个密钥怎么换、换完要重启什么；离职、泄露、出现在截图里时立即换。

## 3. 敏感数据

1. **第三方账号密码、店铺凭证**：AES-256-GCM 加密存储（每条随机 nonce，带认证标签，篡改即解密失败），密文带密钥版本号便于轮换；主密钥没配时拒收，绝不退化成明文存；查看明文要单独权限并审计。
2. **API 密钥（开放接口、服务账号）**：32 字节安全随机数生成，库里只存 SHA-256，明文只在创建时显示一次；可吊销、可设到期；按用户限流；只认指定路径前缀。
3. **会话、令牌**：会话加密密钥落盘的目录要限制权限，能做到的话再用证书或 DPAPI 加密（ASP.NET Core `ProtectKeysWithCertificate` / `ProtectKeysWithDpapi`）——读到这个目录就能伪造所有登录态和签名链接。
4. **长期 token**（如桌面客户端 30 天 token）：要能吊销。token 里带版本号，账号禁用、改密时版本号加 1；每个使用 token 的接口都检查账号状态，不能只在部分接口检查。
5. **签名链接**：有效期、绑定用户和资源，校验逐项核对。
6. **脱敏**：手机号 `188****8821`、身份证前 4 后 4、IP 保留前三段、OpenID 只露尾 4 位。脱敏在后端做，前端遮挡不算。7. **日志**：不打印密码、验证码、token、完整手机号、带 key 的完整 URL；审计里的请求参数按字段名脱敏，脱敏字段名单要覆盖所有密钥类字段。
8. **重置密码**：不要用固定的默认密码（所有被重置的账号在改密前都是同一个密码）。生成随机临时密码，并强制首次登录修改。
9. **敏感个人信息字段级加密**（存身份证、银行卡、健康信息时，正常档起）：按第 1 条的方式加密存储，主密钥与库分开；需要按号码查找的，另存一列带密钥的哈希（HMAC）用于匹配；查看明文单独设权限点并审计。这样数据库备份或导出被拿走时，敏感字段仍是密文。

## 4. 密码存储（参见 `auth-anti-abuse.md` §7）

- 新系统：Argon2id（参考项目的员工账号用 64MB 内存、3 次迭代、并行度 2、16 字节盐、32 字节哈希，存成 `v=1$盐$哈希`）；账号不存在时也跑一次假哈希，耗时一致。
- 共享老表里的无盐 MD5：记为已知风险；限制能读这张表的数据库账号；任何"拿哈希直接当凭证"的协议（免登录签名等）都要加过期时间、一次性随机数，并逐步淘汰。
